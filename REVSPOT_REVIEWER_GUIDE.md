# QualLoop — RevSpot Reviewer Guide

Welcome to the **QualLoop** evaluation repository. This guide provides a concise walkthrough of the application, its statistical foundations, verified setup instructions, and key evaluation questions for the RevSpot team.

> ⚠ **IMPORTANT PROJECT SCOPE & STATUS**  
> QualLoop is an **empirical simulation-based MVP and research prototype** with an offline economic shadow evaluator.  
> It is **NOT** a live ad-platform integration, **NOT** connected to live client ad accounts, and **NOT** a multi-tenant production SaaS. All ad data, leads, and call outcomes displayed in the dashboard are generated by a deterministic scenario simulator. Meta Conversions API (CAPI) events are constructed and hashed in **dry-run mode only** with zero external network transmission.

---

## 1. The Core Problem QualLoop Solves

Standard digital advertising platforms (Meta, Google, TikTok) optimize for top-of-funnel volume: form submissions, clicks, and initial leads. In businesses with sales qualification cycles (B2B SaaS, real estate, healthcare, finance), this creates two major failure modes:

1. **The Reachability Trap:** An uncontacted lead (did not pick up the phone) is treated as "disqualified", artificially depressing the perceived quality of top-of-funnel creative.
2. **The Maturity Delay Trap:** Naive 7-day reporting windows count pending leads as failures, causing ad platforms or media buyers to prematurely pause high-intent cohorts with longer sales cycles.
3. **Small-Sample Point Estimates:** Point-estimate qualification rates (e.g. 1 qualified / 2 contacts = "50%") create illusory winners and losers without statistical credible intervals.

**QualLoop's Solution:** Decouples **Reachability (Contactability)** from **Qualification Intent** using a two-stage Bayesian model ($\text{Beta-Binomial}$), enforces **cohort maturity gating**, quantifies **CPQL uncertainty via Monte Carlo sampling**, and logs every action to an **immutable decision audit trail**.

## 2. Verified Local Setup (5 Minutes)

### Prerequisites
- Python 3.11+
- Node.js 18+ and npm 9+

*(Note: Docker Compose is not required; run standard native processes below.)*

### Step 1: Start the Backend API (Terminal 1)
```bash
cd backend

# Create and activate virtual environment
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

# Install backend dependencies
pip install -e .

# Configure local development environment
cp .env.example .env

# Apply database migrations to local SQLite database (backend/qualloop.db)
python -m alembic upgrade head

# Start FastAPI server
python -m uvicorn api.main:app --host 127.0.0.1 --port 8000 --reload
```
*Verification:* Open `http://127.0.0.1:8000/health` (returns `{"status": "ok", "simulated_data_only": true}`).  
*API Documentation:* Interactive OpenAPI Swagger UI is available at `http://127.0.0.1:8000/docs`.

### Step 2: Start the Frontend Dashboard (Terminal 2)
```bash
cd frontend

# Install frontend dependencies
npm install

# Configure local development environment
cp .env.example .env

# Start Vite dev server
npm run dev
```
*Application Access:* Open your browser to `http://127.0.0.1:3000`.

## 3. 5-Minute Interactive Demo Walkthrough

Once the dashboard loads at `http://127.0.0.1:3000`, follow this workflow:

### Step 1: Portfolio Overview
- Review the top KPI cards: Total Spend, Mature Lead Volume, Expected Qualified Leads (EQL) with 90% credible intervals, and CPQL stability.
- Notice the prominent header warning: *SIMULATED DATA — NOT CONNECTED TO A LIVE AD ACCOUNT*.

### Step 2: Trigger a Simulation Scenario
- In the top navigation bar, click the **"Run Simulation"** button.
- In the modal, select a scenario from the dropdown:
  - `delayed_conversion_trap`: High-intent leads with longer sales cycles (demonstrates maturity gating preventing false pauses).
  - `mixed_portfolio`: A heterogeneous mix of good, marginal, and poor ads.
  - `creative_fatigue`: Creative that deteriorates over time.
- Enter an arbitrary seed (e.g., `42`) and click **"Run Simulation"**.
- Watch the dashboard immediately update with new campaigns, mature cohorts, and Bayesian evaluations.

### Step 3: Inspect Ad Creatives & Credible Interval Bars
- Scroll to the **Creatives & Decision Engine Evidence** table.
- Observe the two-stage visual bars for each creative:
  - **Stage 1: Reachability** (posterior mean + 90% credible interval).
  - **Stage 2: Qualification Intent** (mature contacts only; uncontacted leads excluded).
- Note the status badges: `CONTINUE MONITORING`, `PAUSE AD`, or `EXPLORE`.

### Step 4: Open the Ad Inspector Modal
- Click on any creative row (e.g., `cr-mixed-bad` or an active ad).
- Inspect the mathematical decomposition:
  - Prior vs. Posterior Beta parameters: $\text{Beta}(\alpha, \beta)$.
  - Maturity evidence checklist: Mature leads $\ge 30$, Mature contacts $\ge 20$, Maturity fraction $\ge 60\%$.
  - Exact rule reasoning text generated by the decision engine.

### Step 5: Audit Ledger
- Click the **"Decision Audit Trail"** tab in the top navigation.
- Inspect the immutable, append-only SQLite ledger storing every decision, timestamp, policy version, and supporting metrics.
- Click **"View Raw Payload"** on any entry to see the JSON audit event.

### Step 6: Benchmark Lab
- Click the **"Benchmark Lab"** tab.
- View head-to-head empirical results comparing QualLoop against naive point heuristics across pre-committed holdout simulations.

## 4. Current Capabilities vs. Known Limitations

### What QualLoop Does Today (Implemented & Verified)
- **Two-Stage Bayesian Model:** Pure Python/NumPy implementation decoupling reachability from intent with Beta-Binomial posteriors.
- **Cohort Maturity Filtering:** Distinguishes unresolved leads from disqualified leads using contact and qualification maturity windows.
- **Monte Carlo CPQL Uncertainty:** Draws 2,000 posterior samples to construct CPQL distributions and detects mathematical instability near zero EQL.
- **Append-Only Audit Trail:** Persists all recommendations and statistical snapshots to SQLite/PostgreSQL with schema versioning via Alembic.
- **Offline Economic Shadow Evaluator:** Step 4D.10 isolated shadow runner (`backend/shadow/`) that projects incremental contribution profit ($\Delta \Pi$) and break-even CPQL without mutating live ad state.
- **Automated Test Suite:** 202 backend tests passing in 43 seconds (`python -m pytest backend/tests`).

### What QualLoop Does NOT Do (Explicit Limitations)
- **No Live Ad Mutation:** QualLoop does not connect to Meta Marketing API or Google Ads API; no ad pause or budget modification is dispatched to external platforms.
- **Simulated Scenarios Only:** The UI currently runs on synthetic scenarios generated by the simulator. There is no CSV file upload or live CRM webhook ingestion in the web interface yet.
- **Dry-Run Meta CAPI Only:** The CAPI module validates and hashes event payloads (SHA-256) in dry-run mode; no outbound network requests are made.
- **Exploratory Economic Calibration:** The economic evaluator's probability of profitability is an uncalibrated parameter estimate (not real-world empirical probability) due to deterministic lead volume projections.
- **No Multi-User Auth:** The API and frontend have no login, authentication, or role-based access control.

## 5. Key Questions for RevSpot Reviewers

We welcome RevSpot's candid feedback on commercial and technical viability:

1. **Reachability vs. Qualification:** In your clients' sales funnels, what fraction of leads are typically uncontactable vs. true disqualifications? Does decoupling these two stages align with how your account managers diagnose creative performance?
2. **Sales Cycle Delays:** What are the typical sales qualification windows for your lead-generation clients (e.g. 3 days, 7 days, 14 days)? How do your current reporting dashboards handle pending, unresolved leads?
3. **Economic Hurdle Viability:** For economic decisioning, how feasible is it for clients to provide and maintain segment-level lead values ($V_{\text{QL}}$) and variable intake/telephony costs?
4. **Audit & Compliance Value:** Is an append-only decision audit trail with mathematical evidence valuable for agency-client transparency and quarterly reporting?
5. **Pilot Ingestion Priority:** For an initial non-actioning pilot, which data ingestion path would be most practical:
   - (A) Weekly historical CRM CSV exports?
   - (B) Real-time CRM webhook integration (HubSpot / Salesforce)?
   - (C) Direct read-only ad platform token sync?
